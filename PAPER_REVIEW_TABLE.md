# Paper Review Table

This table is for tracking the week 3 paper-reading task. The goal is not to summarize every technical detail. The goal is to identify what problem each paper solves, how it solves it, how it evaluates the idea, and what gap might still be useful for this project.

| Paper | Problem | Main idea | Implementation angle | Evaluation | Possible connection to this project |
|---|---|---|---|---|---|
| MAS-Attention, MLSys 2025 | Exact attention is hard to accelerate on resource-constrained edge accelerators because attention has quadratic memory and compute growth and edge devices have limited compute and on-chip cache. | Use memory-aware stream processing, multi-tier tiling, and scheduling across heterogeneous compute units. | Splits attention work into tiled vector and matrix streams mapped onto vector processing units and matrix processing units, with cache-aware overwrite to reduce spills. | Reports speedup and energy reduction against FLAT in simulation, plus speedup on a real edge NPU. | Useful for thinking about tiling and scheduling under memory constraints, but less directly connected to my RTX 3090/Triton setup because the hardware target is edge accelerators. |
| FlashInfer, MLSys 2025 | LLM serving needs flexible high-performance attention kernels across diverse inference scenarios, KV-cache layouts, and dynamic requests. | Build a customizable attention engine for LLM serving with flexible KV-cache formats, JIT customization, and load-balanced scheduling. | Attention-kernel library integrated with real serving systems such as SGLang, vLLM, and MLC-Engine. | Kernel-level and end-to-end serving benchmarks, including inter-token latency, long-context inference, and parallel generation. | Very relevant because it connects kernel performance to real serving metrics. This is a strong model for moving beyond isolated microbenchmarks. |
| LServe, MLSys 2025 | Long-context LLM serving is expensive in prefill due to quadratic attention and expensive in decoding due to KV-cache footprint. | Unified sparse attention for both prefill and decode, including streaming heads and KV page selection. | Structured sparse attention and hierarchical KV page pruning for long-sequence serving. | Reports prefill and decode speedups over TensorRT-LLM while maintaining long-context accuracy. | Relevant for application-level workload framing, especially prefill/decode distinction, but it changes the attention algorithm rather than tuning exact fused attention. |
| FlexAttention, MLSys 2025 | FlashAttention is fast but monolithic, making new attention variants hard to explore efficiently. | Use a compiler-driven programming model where users define score/mask modifications and PyTorch lowers them into optimized attention kernels. | PyTorch-facing API with score_mod, mask_mod, BlockMask, and generated fused kernels. | Compares against SDPA and handwritten FlashAttention-family kernels on multiple attention variants, plus end-to-end inference/training cases. | Highly relevant because it is about generating specialized attention kernels from flexible high-level definitions. It may guide the full fused-attention reproduction step. |
| The Anatomy of a Triton Attention Kernel | Portable high-performance LLM attention across GPU vendors is difficult, and a generic Triton kernel needs careful optimization to reach production-level performance. | Build and tune a paged-attention kernel in Triton, showing how algorithmic changes, autotuning, and serving integration improve performance. | Triton paged-attention kernel with tuning and integration into an inference server. | Reports moving from a much slower generic kernel to state-of-the-art level performance after tuning and integration. | Directly relevant to my next Triton step. It suggests that my first QK kernel being slow is expected, and that tuning plus integration choices matter. |
| tritonBLAS | Exhaustive autotuning can be expensive; choosing good Triton kernel parameters analytically may save tuning time. | Predict good GEMM configurations from architecture and problem-shape information rather than trying many configs. | Analytical model for Triton GEMM parameter selection. | Evaluates performance across many GEMM shapes and compares against autotuning approaches. | Relevant to the possible direction of predicting attention configurations instead of exhaustive tuning. It may inspire a simple config selector for attention tile choices. |

## Early Takeaways

The strongest direction still appears to be:

```text
attention kernel configuration selection under realistic LLM workload shapes
```

The QK microbenchmark showed that tile choices matter, but it is too small to explain full attention behavior. The next step should therefore reproduce a full fused-attention implementation and evaluate a small workload table before choosing a paper topic.
